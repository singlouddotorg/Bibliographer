Page index (Level 2)

Adding pages here is what takes a book from Level 1 to Level 2 — a bare book-metadata record becomes a real, browsable page-by-page index. This is for the hand-labor of building it up a few pages at a time, not a bulk importer; a whole book's worth of already-collected data belongs directly in tunebook-library.js instead.

Adding pages alone doesn't flip this edition to Level 2 by itself — that's what the indexStatus field above is for. Set it to complete once the page index here is genuinely done, and Save.

Tunebook Library

Works, Editions, and their Branch relationships — the Work/Edition/State model from the Tunebook Library and File Architecture (v12). This is the one real copy of the data — Edit Tunebook (reached by clicking Edit on a book below) reads and writes it directly, and Export packages a contribution straight from it. There's no separate projection anymore; an edit made in Edit Tunebook shows up here immediately, and vice versa.

New Tunebook

Only Work Code and Title Proper are required — that alone is a real, valid Level 1 record; most Works in this file are exactly that. Fill in the Edition section too if you already know this specific edition's details, and both get created together in one step.

Re-generates tunebook-library.js from the currently loaded data. A round trip (load, then export with no edits) should be lossless — semantically identical to what was loaded, field for field.

Export

Different formats for getting a book's data out of this app, for different purposes. Contribution is the main one — packaging a book to send the maintainer for review — but it's one of several; more formats belong here too as they come up, each its own section below.

Contribution Export

Package one book from your working copy as a contribution file to send the maintainer for review. This does not generate or replace tunebook-library.js (use Save tunebook-library.js above for that), and exporting doesn't make a book available in Minutes — accepted contributions may appear in a future Tunebook Library release.

Substack Export

Copy-paste-ready text for a Substack post, matching the format used on the Sacred Harp Bibliography Project. Index lists just this book's own facts plus page number and song name — works for any book with at least a page index. Full adds every enriched field this book has (meter, attributions, first line, scripture, historical notes) — needs a real Tunebook File (Level 3).

Bulk Edit

Every book in the Library — every real Edition, whatever its Level, plus every bare Work with no Edition at all yet — in one editable table. What's narrow here isn't which books show up; it's which fields can be touched: only the ones with nothing to do with page data. Title Proper, Subtitle, Common Name, Compiler, Publication Year, Shape System, SHMHA Code, Badge Colour/Badge Text, and Minutes Visibility — a Level 2 or 3 Edition can be just as likely to be missing one of these as a Level 1 one, and this fills them in the same way either way. A bare Work has no place to hold Subtitle, Common Name, Compiler, Publication Year, colours, or Minutes Visibility until it has a real Edition — give it an Edition Identifier Year and one of those fields, and saving that row creates a real Level 1 Edition (Work Code + year) to hold them. Title Proper, Shape System, and SHMHA Code exist on both, so on a bare-Work row they edit the Work's own copy directly, whether or not that row also gets a new Edition.
